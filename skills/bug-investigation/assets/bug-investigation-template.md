# BUG-INVESTIGATION

## Context

Issue:
Problem Summary:

## Current State

Describe the currently observed system behavior.

## Problem Analysis

Document the understanding developed during investigation.

Include observations, findings, suspected causes, and supporting evidence when
available. A definitive root cause is not required when the evidence is
inconclusive.

## Affected Components

Document known or suspected affected areas, such as:

- Modules
- Services
- Database objects
- Integrations
- Workflows
- UI areas

## Impact Assessment

Describe the observed business, operational, and technical impact.

## Assumptions

Record assumptions made during the investigation.

## Open Questions

Record unresolved information that may influence architecture decisions.

## Recommended Direction

Provide high-level correction guidance while remaining implementation-neutral.

Examples:

- Input validation review required.
- Search workflow should be re-evaluated.
- Integration contract requires investigation.

Do not specify files, line numbers, database indexes, refactors, or other
implementation steps.

## Decision Summary

Summarize the investigation outcome, remaining uncertainty, and readiness for
ARCHITECTURE work.
